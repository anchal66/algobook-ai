# AlgoBook AI (v2)

AI-powered, LeetCode-style practice platform. Problems are generated by GPT,
**verified on Judge0 before anyone sees them**, and solved in a Monaco workspace
with server-side Run/Submit, per-user practice intelligence and a Pro plan.

> v2 is being rebuilt module by module. The plans, status and decisions live in
> [`docs/modules/`](docs/modules/00-MASTER-PLAN.md) — read `00-MASTER-PLAN.md`
> first, then `STATUS.md`.

## Stack

Next.js 16 (App Router, Turbopack, TypeScript 7) · React 19 · Tailwind v4 + shadcn/ui ·
Firebase Auth + Firestore (client read-only, all writes via firebase-admin) ·
Judge0 CE (RapidAPI, self-host ready) · OpenAI (gpt-5.6-luna) · zod · vitest.

## Setup

```bash
npm install
cp .env.example .env.local        # fill in the values (see comments in the file)
npm run dev                       # http://localhost:3000
```

Required services:

1. **Firebase** — a project with Google sign-in enabled; put the service-account
   JSON under `firebase/` (git-ignored) and point `FIREBASE_SERVICE_ACCOUNT_PATH` at it.
   Deploy rules and indexes once: `firebase deploy --only firestore:rules,firestore:indexes`.
2. **Judge0** — a RapidAPI key for `judge0-ce.p.rapidapi.com`, or a self-hosted
   instance (see `docs/modules/reference/JUDGE0-SELF-HOST.md`).
3. **OpenAI** — `OPENAI_API_KEY` (Module 02).
4. **ADMIN_UIDS** — comma-separated Firebase UIDs allowed to use admin routes and
   `/dev/api-smoke`. Find yours: `npm run db:find-uid -- --email you@example.com`.

| Command | What it does |
|---|---|
| `npm run dev` / `build` / `start` | Next.js |

## Architecture (Module 01 — Foundation)

```
src/
  app/api/**            route handlers: every call authenticated with a Firebase ID token
  lib/env.ts            zod-validated environment (fails fast)
  lib/api/              ApiError envelope + handler() wrapper (zod body/query, auth, quota, structured logs)
  lib/auth/             requireUser (verifyIdToken + plan cache + quotas), PLAN_LIMITS
  lib/data/             schema.ts (zod schema v2 = source of truth) + typed Firestore repositories
  lib/judge/            Judge0 batch client, per-language assembler, canonical stdin encoding, checkers, service
  lib/practice/stats.ts stub counters (Module 04 replaces with the real intelligence engine)
  lib/api-client.ts     apiFetch() for the browser — attaches the ID token, throws ApiError
  types/index.ts        types derived from the zod schemas (legacy v1 shapes in types/legacy.ts)
scripts/                firestore-wipe, seed-templates, seed-sample-problem, grant-plan, find-uid
firebase/               firestore.rules (v2, deny-by-default) + firestore.indexes.json (incl. vector index)
docs/modules/           master plan, per-module specs, STATUS.md, DECISIONS.md, reference docs
```

### API (Module 01)

All routes require `Authorization: Bearer <Firebase ID token>` and return errors as
`{ error: { code, message, details? } }` (`401 UNAUTHENTICATED`, `402 PAYMENT_REQUIRED`,
`429 QUOTA_EXCEEDED { resetAt }`, `404` for anything you do not own).

| Route | Purpose |
|---|---|
| `GET/PATCH /api/me`, `PATCH /api/me/settings`, `POST /api/me/username`, `GET /api/users/username/check?u=` | profile, settings, username |
| `GET/POST /api/projects`, `GET/DELETE /api/projects/:id` | projects with denormalised progress |
| `GET /api/problems`, `GET /api/problems/:id?lang=` | explore list; public problem + starter + sample tests (hidden tests never leave the server) |
| `POST /api/run` | up to 6 cases in **one** Judge0 batch |
| `POST /api/submit` | sample + hidden tests in one batch → verdict, beats %, submission, activity, project progress, user counters |
| `GET /api/submissions`, `GET /api/submissions/:id`, `PUT /api/drafts/:id`, `PUT /api/notes/:id`, `GET /api/activity` | history, autosave, heatmap |
| `POST /api/problems/:id/report`, `GET /api/templates`, `/api/subscription/*` | flagging (auto-retire at 2), templates, payments |

Problem I/O contract (stdin/stdout encodings shared by all languages):
`docs/modules/reference/IO-FORMAT.md`.
