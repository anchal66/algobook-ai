# Pre-launch audit — 2026-09-08

Four read-only reviews (AI cost & model fit · Module 05 pages · workspace · API/security/ops) run after Module 05 shipped, plus a
production incident found the same evening. This file records what was fixed the same day and what remains, so the next session

## Production incident (fixed)
- **Every `/api/*` route returned 500 on algobookai.cognitivesquad.com.** Vercel ran the functions on Node.js 20, where `require()` of an
  ES module fails; `firebase-admin/auth` → `jwks-rsa` → `jose` v6 hits exactly that at import. Locally Node 22 hides it.
  Fix: `"engines": { "node": "24.x" }` in `package.json` (Vercel picks the runtime from it; the dashboard was already warning that Node 20
  builds stop on 2026-10-01). Also: a missing `RAPIDAPI_KEY` no longer throws inside `env.load()` (which took down `/api/me`); the judge
  client returns a 503 with a clear message instead.
- Env added on Vercel (production): `NEXT_PUBLIC_APP_URL`, `ADMIN_UIDS`. **Owner still has to add `CRON_SECRET`** (≥ 16 random chars) or
  the three crons in `vercel.json` are rejected: `openssl rand -hex 24 | vercel env add CRON_SECRET production`, then redeploy.
- Firestore rules deployed as deny-all (`npm run db:deploy`): the browser never reads Firestore in v2.

## How the AI is used to generate problems (for the owner's question)
Recommender picks topic + difficulty → reuse search over the verified pool (embeddings) → **one structured-output call to
`gpt-5.6-luna`** produces the full spec (statement, params, examples, sample tests, ≥ 8 hidden tests, Java starter/reference/driver, 3 hints)
→ static validation (identifiers, tags, stdin encoding, duplicates) → embedding duplicate check → **the reference solution is executed on
the judge against every sample and hidden test** → if it fails: adopt the reference's outputs for ≤ 30 % of hidden cases when all samples
pass, else repair with judge feedback (Luna, then Terra) → only then persisted as `verified`. Other languages' drivers are generated and
verified against the same hidden tests before they are enabled. Editorials/hints are generated once and shared; the tutor is scoped and
refuses full solutions before an AC. After publication: users flag; two flags retire; admins can retire/restore and **re-verify** (re-runs every
stored reference on the judge; disables a failing language, retires on a failing Java reference).

What can still be wrong after all that: (1) a statement that is ambiguous or does not match the tests (execution cannot catch meaning);
(2) hidden tests that are too weak, so a wrong user solution passes; (3) a reference that is wrong *and* self-consistent on the samples
(the adoption path trusts it); (4) editorial code and hints are text, never executed. Mitigations shipped today are below; the next big one
is a brute-force cross-check (see "Remaining").

## AI cost & model fit — decided policy (Luna / Terra / Sol only)
Observed: generate + repair = 91 % of spend; ~37 % of generations needed a repair; one Terra repair ≈ 4× a Luna generation; truncated
"degenerate loop" generations cost 2× a good one and were discarded.
- **Generation:** Luna. Effort tiered by difficulty — Easy `medium` / 12k tokens, Medium `high` / 14k, Hard `high` / 16k (`generationPolicyFor`).
  Size discipline is now in the base prompt for Easy/Medium (was only in the retry).
- **Repair #1:** Luna, effort by feedback kind — static contract errors `medium`, judge failures `high` (`repairEffortFor`); `xhigh` dropped.
- **Repair #2:** Terra `medium` kept for the live path only (a user is waiting); pre-generation uses a Luna-only ladder.
- **Sol:** no justified use; even an admin "premium regenerate" is better served by Terra `high`.
- **Deterministic repair before any model call:** test inputs written in the human form (`[2,7,11,15]` / `9`) are re-encoded with the same
  `fromHuman` the workspace uses (`canonicalizeInputs`) — previously a $0.005–0.014, 40–110 s repair.
- Every `aiUsage` row now carries `tags` (difficulty, repair round, feedback kind) so the admin console can attribute cost per tier.
- Unchanged and fine: drivers (Luna medium), hint3/explain/review/chat/insights (Luna low), completion (Luna none), editorial (Luna medium).
Expected effect: per verified problem ≈ $0.025 → ≈ $0.015. **Not yet re-measured** — run `npm run ai:eval -- --n 15 --mix 5,7,3` with
`JUDGE_BACKEND=local` before trusting the tiers.

## Fixed today (by area)
**API / security / cost**
- Global daily Judge0 budget (`system/judge`, `JUDGE0_DAILY_CAP`, default 45 on the RapidAPI free tier) with an honest 503; Judge0 429 mapped
  to the same message; judge internal errors are never persisted as a Runtime Error (503 instead); poll timeout 20 → 40 s.
- `/api/projects/:id/next`: atomic quota reserve (check + increment in a transaction) with refund on failure/reuse; one generation per project
  at a time (5-min lease → 409). Client aborts the stream on unmount and never navigates after abort.
- Driver generation on demand charges the `run` quota; `insights` `force` only for admins inside the 10-min window.
- Interview restrictions enforced server-side (hints, editorial, chat, review, explain → 403 during an active session).
- Contact rate limit is a per-IP hourly counter transaction; activation checks `serviceName`, `currency` and requires `amount`; cron secret
  compared in constant time; bounded scans on subscriptions/interviews/invoices; `timeSpentSec` clamped both sides; legacy
  `usernameChangesLeft` defaults to 2; env validated at cold start (`instrumentation.ts`).
**Pages**
- `useQuery`: refcounted keys so `invalidate` never re-fires a POST-backed query nobody is showing (the insights double-generation);
  errors are not sticky; stale responses cannot overwrite newer ones; insights keyed apart from `/api/projects`.
- 401 anywhere → sign out + `/login?next=`; `useMe` has an error state with Retry and is reset on sign-out / account switch; auth timeout falls
  back to `auth.currentUser` instead of flashing `/login`.
- Friendly error copy (`describeError`/`errorText`) with reset time for 429 and a plan CTA for 402, used by every toast; visible error + Retry
  on the Continue/Daily cards, recommendations, badges, project overview (404 vs other); onboarding step 2 links to the first project;
  "End interview" confirmation and per-row busy; leaderboard "Load more" errors surfaced; Explore filters driven by the URL (Back/Forward
  exact); mobile: activity table scrolls, settings section nav, Upgrade pill reachable; topic chips are `aria-pressed` toggles; theme control
  shares the keyboard-navigable `Segmented`.
**Workspace**
- Run/Submit results are dropped if the user navigated to another problem meanwhile; mobile jumps to the console on run and stays there;
  clearer copy for judge/upstream/conflict errors.

## Remaining (prioritised)
1. **Judge0 capacity** (D-05): 45 batches/day is not a launch configuration. Self-host (`docs/modules/reference/JUDGE0-SELF-HOST.md`) or a paid plan,
   then set `JUDGE0_DAILY_CAP=0`.
2. **Brute-force cross-check** in generation: add `brute.java` to the spec, run it on all tests, adopt only values where brute and reference agree
   (≈ $0.001 and +1 batch per problem). Then constraint-derived stress inputs and small-input fuzz (needs the self-hosted judge).
3. Client-trusted submit `meta` (hintsUsed, editorialViewed, localHour) can game XP/badges → record hint/editorial usage server-side and read it
   in the submit transaction; idempotency key on `/api/submit`.
4. `/api/public/stats` and the hourly leaderboard job do full scans; move counters/aggregates into the cron and serve them from `leaderboard/meta`.
5. Mobile Lighthouse (landing 74, signed-in pages 60–64): remaining levers are lazy-loading the Firebase Auth SDK behind the auth gate,
   server-rendering the marketing hero, and splitting recharts out of the dashboard's first load.
6. UTC day keys: streaks/daily/quotas flip at 00:00 UTC; show local reset times or accept a client timezone offset on submit.
7. Notifications are stored preferences only; `contactMessages` has no admin UI; a retired problem stays servable by direct id.
8. `readJson` has no size cap; drafts/notes accept any `problemId`; `verifyIdToken(token, true)` on every request costs an Auth RPC.
